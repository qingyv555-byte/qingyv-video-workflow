# Project memory

For long, interruption-prone, or multi-session work, keep three documents with one authority for each kind of fact.

## Direction

Store current user requirements, quality targets, scope boundaries, and acceptance criteria. Update it when the requested direction changes.

## Execution blueprint

Store the project path, branch, stack, current phase, active versions, important files, evidence, verification results, remaining work, risks, and the next concrete step. This is the recovery entrypoint after interruption.

## Decisions and failures

Store why important choices were made, which approaches were rejected, what failed, and what was learned. Historical states remain history; they must not be read as the current plan.

Link evidence instead of copying long logs, contact sheets, or reports into memory. Distinguish implemented, rendered, verified, integrated, and accepted. Before context exhaustion or a risky transition, write a compact checkpoint and then verify it against actual files when work resumes.
